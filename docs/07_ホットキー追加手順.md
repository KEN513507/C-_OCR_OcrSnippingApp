# 🔑 ホットキー追加手順（将来拡張ガイド）

最終更新: 2025-11-03  
対象バージョン: OcrSnippingApp v2.x

---

## 概要

本書は「将来、ホットキーを追加（複数化）する」際の手順と設計選択肢を示します。現在は「未設定（空欄）を許容・自動フォールバック無し」という運用です。これを保ちつつ、追加のホットキーを最小差分で導入する方法（方針A）と、スケーラブルなコレクション設計（方針B）を提示します。

---

## 現在のホットキー設定（単一）

### 1. 設定方法
- 対象ファイル: `appsettings.json`（配布物と同じフォルダ、または `%APPDATA%\OcrSnippingApp\appsettings.json`）
- `OcrSnipping` セクションの `HotkeyModifiers` と `HotkeyKey` を編集する。

```json
{
  "OcrSnipping": {
    "HotkeyModifiers": "Ctrl+Shift",
    "HotkeyKey": "W",
    "OcrMode": "DocumentTextDetection",
    "Notifications": true,
    "TimeoutMs": 10000,
    "LanguageHint": "ja"
  }
}
```

- 空文字（`""`）のまま保存するとホットキーは無効化される。片肺入力（修飾子のみ／キーのみ）は保存時に空欄へ正規化され、Warn ログが出力される。

### 2. 競合の確認手順
1. **既存ショートカットの確認**: Windows 標準ショートカットや他アプリのホットキーと重複しないか事前確認する。
2. **登録結果のログ確認**: アプリを起動し、`%APPDATA%\OcrSnippingApp\Logs` の最新ログに `ホットキー登録に失敗しました` が出ていないか確認する。失敗した場合は別の組み合わせに変更する。
3. **動作確認**: 設定したホットキーでスニッピングが起動し、OCR結果がクリップボードに入るかを確認する。

**PowerShell での衝突テスト（任意）**
```powershell
# 付属ツールによる衝突チェック例
cd tools\HotkeyProbe
.\HotkeyProbe.ps1 -Modifiers 'Ctrl+Shift' -Key 'O'

# 配列を使って一括検証する例
@(
  @{Mods='Ctrl+Shift'; Key='O'},
  @{Mods='Ctrl+Alt';   Key='Q'},
  @{Mods='Alt+Shift';  Key='S'}
) | ForEach-Object {
  $result = .\HotkeyProbe.ps1 -Modifiers $_.Mods -Key $_.Key
  "{0}+{1} => {2}" -f $_.Mods, $_.Key, $result
}
```
`REGISTER_OK` が返れば user32.dll への登録に成功（少なくとも OS レベル競合なし）です。`REGISTER_FAIL:1409` などが出る場合は既に同じキーが占有されています。

## 設計方針

- 方針A（最小差分・早く安全に）
  - 追加の2本目ホットキーとして `Hotkey2Modifiers`, `Hotkey2Key` を AppSettings に追加。
  - 既存の登録処理を小変更で複製（同じスキップ/無効化ルールを適用）。
  - UI/トレイ表示は「スクリーンショット（複数表記）」または先頭のみ表示でも可。

- 方針B（将来拡張・スケーラブル）
  - `List<HotkeyBinding>`（action, modifiers, key）に再設計。
  - アクション識別子（"Capture" など）ごとに任意本数のホットキーを登録可能。
  - 設定UIと保存形式の移行（マイグレーション）が必要。リスク高・工数大。

現時点の推奨: 方針A（必要になったらBへ移行）。

## 方針A: 実装手順（最小差分）

1. 設定モデルの拡張
   - ファイル: `src/OcrSnippingApp/Services/SettingsService.cs`
   - `AppSettings` に以下を追加（空欄許容・未設定は無効）
     - `public string Hotkey2Modifiers { get; set; } = string.Empty;`
     - `public string Hotkey2Key { get; set; } = string.Empty;`
   - `SaveSettings()` はそのまま（JSONへ直列化される）

2. 検証（ValidateSettings）の方針
   - Hotkey2 も Hotkey1 と同様に「空欄を許容」「無効値は空へ正規化」。
   - 片肺入力（mods だけ / key だけ）は Warn ログを出し、両方空に正規化。

3. 保存APIの正規化
   - `UpdateHotKey` と同等のロジックを `UpdateHotKey2` として追加（または共通ヘルパー化）。
   - ルール: 片肺入力は Warn → 両方空欄に正規化。

4. 登録処理（MainForm）
   - ファイル: `src/OcrSnippingApp/Forms/MainForm.cs`
   - 既存 `RegisterHotKey()` 相当を
     - Hotkey1 用と Hotkey2 用の2回呼び出す（共通メソッド化推奨）。
     - どちらも「空欄→登録スキップ」「Enum.TryParse 失敗→登録スキップ」。
     - Info ログ: `Hotkey disabled: Registration skipped.` を各ホットキーで個別に出すか、まとめて1行でも可。

5. トレイ表記
   - 例: `スクリーンショット（Ctrl+Alt+C / Shift+Alt+S）` のように複数表示。
   - 未設定時は「ホットキー未設定」。片方だけ設定時は単独表示。

6. UI（任意）
   - 設定フォームに 2 本目の入力欄を追加。
   - 保存ボタンのハンドラは Hotkey1 と同じロジックで正規化。

7. ログ方針
   - 未設定: Info（登録スキップ）。
   - 片肺入力→正規化: Warn。
   - 競合（RegisterHotKey失敗）: Warn（ダイアログは出さない）。

## 受け入れ基準（Definition of Done）

- 空欄でもエラーせず起動。両ホットキーとも未設定なら完全スキップされる。
- 片肺入力は保存時に両方空に正規化され、Warn ログが出る。
- 有効な2本のホットキーが共存して動作する（どちらでもキャプチャ起動）。
- トレイ/メニュー表記が実態に一致（未設定/片方/両方）。
- 既存の UX（未設定を許容・フォールバック無し）を維持。

## 動作確認コマンド（PowerShell）

プロジェクト直下で実行。

1) 設定値の確認
```powershell
$j = Get-Content .\appsettings.json -Raw | ConvertFrom-Json
"Hotkey1: '{0}' '{1}'" -f $j.OcrSnipping.HotkeyModifiers,$j.OcrSnipping.HotkeyKey
"Hotkey2: '{0}' '{1}'" -f $j.OcrSnipping.Hotkey2Modifiers,$j.OcrSnipping.Hotkey2Key
```

2) 登録スキップ/正規化のログ確認
```powershell
$log = Join-Path $env:APPDATA 'OcrSnippingApp\Logs'
Get-Content (Get-ChildItem $log -Filter *.log | Sort LastWriteTime -Desc | Select -First 1).FullName -Tail 120 |
  Select-String -Pattern 'Hotkey disabled: Registration skipped|partial input -> normalized'
```

3) コード確認（痕跡）
```powershell
Select-String -Path .\src\OcrSnippingApp\**\*.cs -Pattern 'Hotkey2Modifiers|Hotkey2Key|RegisterHotKey' -Context 1,1
```

## ロールバック手順

- 2本目の設定値を空欄へ戻す（未設定）。
- `RegisterHotKey` 呼び出し箇所から Hotkey2 分をコメントアウト（または条件付き）。
- UI から 2 本目の欄を非表示（設定は残しても無害）。

## よくある質問（FAQ）

- Q: 自動フォールバック（例: 衝突時にCtrl+Shift+Cへ）は？
  - A: 採用しません。意図しない動作を避けるため、明示設定のみに従います。

- Q: 片方だけ入力して保存したい場合は？
  - A: 仕様上、片肺入力は無効（両方空）に正規化されます。両方正しく入力してください。

- Q: 今後、アクションごとに複数ホットキーを割り当てたい。
  - A: 方針B（List<HotkeyBinding>）を検討してください。移行計画とUI刷新が必要です。
